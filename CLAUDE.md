# Контекст для Claude Code

Тестовое задание: конвейер проверки бизнес-моделей. ТЗ, решения и статус — ниже. Пользователь пишет по-русски, отвечать по сути, без воды.

## Что это
YC Directory → 15 моделей → фильтр по 5 критериям заказчика → агент А («почему не сработает») + агент Б (проверяет источники, видит только факт) → оценщик → карточки → HTML-рейтинг.
Критерий рейтинга (от заказчика): шанс за 3 месяца запустить тест, проверить спрос и получить первую оплату.

## Структура
- `config.yaml` — всё настраиваемое; `config.budget.yaml` — дешёвый профиль (`BIZPIPE_CONFIG=config.budget.yaml`)
- `pipeline/`: `collect` → `filter` → `agents` → `scoring` → `render`; `llm.py` — цепочка провайдеров, ретраи, учёт стоимости
- `prompts/*.md` — промпты, `templates/report.html` — отчёт, `scripts/make_demo.py` — демо без ключа
- `DECISIONS.md`, `KNOWN_ISSUES.md`, `VIDEO_SCRIPT.md` — сдаточные документы

## Договорённости с заказчиком (не менять без спроса)
- Сбой LLM: ретраи → запасная модель → статус `not_verified` (не в рейтинг и не в отказы)
- Противоречия: консервативное значение, все версии в паспорте, метод `needs_human`, уверенность ≤0.5
- $300M = капитализация аналога; комиссии маркетплейса = повторяющиеся деньги; юрисдикция EU+US
- 6-й критерий «оплата за 3 мес» не добавлять в фильтр — штраф в рейтинге
- Собственнику баллов не показывать: вердикт словом, срок первой оплаты диапазоном, шанс словом. Баллы — только внутри (`data/cards.json`)
- Структура карточки согласована: Идея · Заплатят · Деньги · Путь к оплате · Оценка (✔●✖) · Риски (+ «→ для нас») · Первые шаги · свёрнутые «Источники и проверка»
